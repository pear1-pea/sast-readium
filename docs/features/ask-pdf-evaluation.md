# Ask PDF：第一批切分与证据验证

上下文按字符截取会把证据尾部条件截掉，同时引用仍保留完整块信息。
第一批改为只发送完整块，并为 embedding 请求禁用静默截断。
离线评测用于定位证据损失，尚不证明真实文档上的回答质量改善。

日期：2026-10-22。范围对应 [待办](ask-pdf-todo.md) 的 01 基础设施、02 部分和 03。

## 实现与回归

- `ContextAssembler` 跳过放不下的块，继续选择后续块，保持正文、原文位置和引用一致。
- 回归覆盖精确预算、预算少一个字符、中英文和代理对、尾部条件、后续小块及引用校验。
- `/api/embed` 显式发送 `truncate: false`，错误保留 HTTP 状态和服务端诊断。
- HTTP fixture 覆盖成功、超限、模型不存在、无效响应、超时、取消及服务不可用。
- Coordinator 回归确认 embedding 失败时索引仍 Ready，词法检索仍返回证据。

## 离线评测

新增 `test_rag_evidence_baseline`：合成页文本 → PdfChunker → SQLite FTS5 →
HybridRetriever（仅词法）→ ContextAssembler。六类问题覆盖定义、流程、条件、例外、
跨页和重复召回。标注使用文档 hash、页码和原文范围，不依赖 chunk ID。

证据 recall 为被返回范围完整覆盖的必要证据条数占比，忽略切分时修剪的空白。
每题等权平均。重复量按同页原文范围重合计算，不是语义相似度。

| 切分配置：目标/最大/重叠 | 字符预算 | recall@3 | 上下文证据 recall |
| --- | ---: | ---: | ---: |
| 800/1200/120（当前） | 12000 | 0.916667 | 0.916667 |
| 800/1200/120（当前） | 700 | 0.916667 | 0.750000 |
| 800/1200/0 | 12000 | 0.916667 | 0.916667 |
| 800/1200/0 | 700 | 0.916667 | 0.833333 |
| 180/260/120 | 12000 | 0.833333 | 0.833333 |
| 180/260/120 | 700 | 0.833333 | 0.833333 |

这里的字符是 QString UTF-16 code units，不是 token；不同配置也不保证实际输入量相等。
表格使用完整块组装后的结果，不是旧版与新版的收益对照。跨页问题始终只覆盖两条必要
证据中的一条。700 字符预算下跳过大块会降低覆盖率，是后续邻近扩展与预算选择需要
解决的取舍。样本规模很小，保留默认切分参数，暂不采用某个实验配置。

## 复现

在仓库根目录执行：

```bash
cmake --build build --config Release --target test_rag_evidence_baseline
QT_QPA_PLATFORM=offscreen READIUM_RAG_EVAL_REPORT="$PWD/build/rag-evidence-baseline.json" \
  ./build/tests/unit/test_rag_evidence_baseline
```

报告包含源文本、标注范围、全部 chunk、召回结果、实际组装正文、覆盖率、重复字符、
索引块数、索引文本量和阶段耗时。输出路径必须为绝对路径；不设置环境变量时只运行测试。
生成报告位于 git-ignored 的 `build/`，不自动上传。

## 第二批：统一上下文预算（02 剩余项）

日期：2026-10-22。范围对应待办 02 的预算与 tokenizer 两项。

- 预算同时覆盖系统提示、问题、历史、证据和输出预留；证据优先，历史只在剩余预算内按完整轮次加入，放不下就整轮丢弃，不切断问句和回答。
- 估算值 = 各消息内容的 UTF-8 字节数 + 每条消息固定开销，作为 BPE tokenizer 的保守上界。它不是真实 tokenizer，估算大于实际，因此不会溢出窗口。
- 请求显式发送 `num_ctx = contextWindowTokens` 与 `num_predict = maxOutputTokens`，服务窗口不再取决于 Ollama 版本默认值。
- 服务在最后一帧返回 `prompt_eval_count`，coordinator 逐次记录实际 token 数与估算值；实际值超过估算时输出 warning，作为估算需要收紧的信号。
- 默认窗口 16384。实测 4096 窗口（输入容量约 2816 字节）放不下单个 1200 字中文块（约 3600 字节），会让几乎所有中文问题返回预算错误，因此不采用。
- 回归：`test_chat_budget` 覆盖整块保留、超大块跳过、历史后缀完整、预算少一字节、问题不截断和默认窗口容纳大块；`test_rag_p3` 覆盖请求体携带 `num_ctx`/`num_predict`/系统提示、超预算请求被拒绝，以及 `prompt_eval_count` 回传。

未验证或未采用：

- 未在真实 Ollama 模型上跑长上下文或超限场景，仍使用本地 HTTP fixture。
- 未查询模型自身的 `context_length`，`num_ctx` 固定为 16384 作为运行窗口；若所选模型训练窗口更小，需要后续按模型设置。
- 字节估算对英文约保守 3–4 倍，证据量仍受 12000 字符上限约束；窗口大小与估算方式属于 05 的对照实验。

验证：`cmake --build build --config Release` 退出码 0；`ctest --test-dir build
--output-on-failure` 26/26 通过（含新增 `test_chat_budget`）；`pre-commit run
--all-files` 通过。

## 第三批：邻近扩展、切分策略与 token 预算评测

日期：2026-10-22。范围对应 01 的 token 预算对照、04、05 和 06 的评估项。

### 邻近扩展与范围合并（04）

检索仍以小块为单位，命中后补充阅读顺序上前后各一个块，只允许同页或相邻页，
单条合并文本上限 2400 字符。重叠或相接的原文范围合并成一条证据：重叠部分只
保留一次，`locations` 取区间并集，引用沿用组内排名最高块的 `chunkId`，因此页
码跳转与高亮仍可定位。合成基线上，扩展前后的上下文证据召回（token 窗口
16384，Top K = 3，四组切分配置）：

| 切分配置 | 扩展前 | 扩展后 | 上下文重复字符 |
| --- | ---: | ---: | ---: |
| 800/1200/120（当前） | 0.917 | **1.000** | 0 |
| 800/1200/0 | 0.917 | **1.000** | 0 |
| 800/1200/120 + 句子回带 | 0.917 | **1.000** | 0 |
| 180/260/120 | 0.833 | **0.917** | 0 |

跨页问题由 0.5 提升到 1.0，是本次唯一可归因的质量改善。重复字符为 0 是因为
合并按原文范围去重，不是检索去重；索引层仍保留 overlap 带来的重复文本。

### 切分边界与 overlap（05）

- 新增 `PdfChunkerOptions::sentenceAwareOverlap`：重叠起点前移到最近的句末，
  回看上限 240 字符，避免新块以半句话开头。
- 四种配置在合成基线上 recall@3 完全一致（0.917 / 0.917 / 0.917 / 0.833），
  差距来自块大小而不是 overlap 或句子回带。因此保留当前默认配置，不切换策略。
- 每轮只改变一个参数：`no-overlap` 只改 overlap，`sentence-overlap` 只改回带
  开关，`smaller` 只改块大小。
- 索引入库现在记录 `chunker_policy`（`target/max/overlap/sentences`）。策略不
  一致时文档整体重建，旧 chunk、FTS 和向量一起替换；schema 从 v1 迁移到 v2，
  旧库的空策略不会匹配任何新策略，只会重建一次。

### 结构增强评估（06）

- `sectionPath`：从 Poppler outline 构造“父标题 › 子标题”，按页取最近的目录
  项，随页写入 chunk。它只进入重排权重，不作为原文证据发送，因此不会制造无法
  引用的事实。无目录的文档保持空值，行为不变。尚未在带目录的真实 PDF 上验证。
- 父子分块：邻近扩展已把合成基线召回提到 1.0，条件“扩展仍不足”不成立，暂不
  立项；若真实语料显示长距离前提仍丢失，再按父块范围与最终预算重新评估。
- Contextual Retrieval：需要本地生成模型逐块改写，当前无可用的真实模型基线，
  无法比较成本与收益，保持待定。
- late chunking：Ollama 的 `/api/embed` 不返回 token 级表示，现有本地服务能力
  无法实现，未立项。语义切分与更换 embedding 模型需要真实模型对照，等 01 的
  真实语料基线完成后另行立项。
